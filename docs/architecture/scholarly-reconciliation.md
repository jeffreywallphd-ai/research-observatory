# Scholarly identity and duplicate review

Source assertions retain the exact accepted import member or connector record,
source revision, original values, rights and normalized identifiers. Exact
unique compatible identifiers may link a Work. Similarity scores only propose
human review; they are not probabilities and never authorize a merge.

Schema 15 adds sealed complete membership for every Work revision. Migration
from the literal schema-14 predecessor reconstructs each historical membership
prefix in numeric revision order. Original source assertions, Work revisions,
receipts, provenance and decisions remain unchanged. A verified backup precedes
the transactional migration; interrupted backfill rolls back to schema 14.

Human merge, split and assignment plans bind current Work revisions, complete
source partitions, every affected inbound alias, explicit surviving identities,
retained conflicts and an evidence digest. Core previews downstream effects and
binds the preview to current Intent, privacy and actor authority. Publication
appends the decision, active/retired Work revisions, membership seals, aliases,
provenance, outbox and dependency-impact intent in one transaction. Identical
authorized retries return the original outcome. Changed command reuse or stale
predecessors fail without publishing partial facts. Reversal is another decision.

Current identity routing uses sealed current membership. An old receipt remains
the original receipt even after its assertion is reassigned. Revision-qualified
history does not follow current aliases. Inspection exposes `requires-review`
when material inputs or their recorded change roots are affected. New outputs
cannot consume those inputs, including a prior human decision or an affected
leaf among inputs packed into bounded provenance manifests. A historical
predecessor retained solely for audit is not a material input.

The deterministic duplicate kernel exposes fresh and prepared-input paths with
the same normalization, blocking, ranking, configuration and limits. Project-local
feature snapshots bind the immutable assertion/source revision, source digest,
input fingerprint, algorithm, normalizer and feature versions. Cache reads still
resolve current source rights. The cache is a derived projection and grants no
authority to inspect, derive or merge. The original DBLP-ACM scoring freeze and
first qualification observation remain retained; the later cache bridge declares
that qualification labels have already been observed.

Accepted workflow output inventory is independent of the Task Center's recent
window. Its immutable snapshot binds activity selection and provenance segment
checkpoints; paging cursors bind that snapshot's fingerprint. Enumeration checks
job, succeeded attempt, output manifest, canonical revision, completion event and
outbox identity. Missing or substituted acceptance references deny enumeration
instead of hiding rows. Later accepted jobs appear only in a newly opened
snapshot. Inventory addresses still require the source owner's current rights
checks before content is used.

Source owners expand accepted outputs into exact retained record addresses.
Import inspection checks the accepted attempt's preparation, complete staged
decisions and effective import identity against its manifest. Identical scientific
identity can reuse a manifest across requests; a changed draft cannot borrow an
older output. Streams verify that identity once and re-enter current project and
source rights for every bounded page. Excluded rows advance the cursor, so an
empty emitted page does not mean exhaustion.

Connector lookup authenticates the original confirmed operation and all bounded
continuation branches. Each parent edge preserves definition, Intent, policy,
configuration and executor authority; each accepted output must match the exact
invocation result. A newer active branch cannot hide an accepted historical one.
This local history lookup grants no new network execution or egress consent.

The initial batch input contract freezes the inventory, accepted Intent, privacy,
session and scoring configuration. The durable reconciliation/candidate worker and
desktop review journey remain CAP-04.S03.T02 integration work. These foundation
contracts and development checks do not establish task or Wave completion.
