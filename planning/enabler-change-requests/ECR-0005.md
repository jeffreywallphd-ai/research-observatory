# ECR-0005 — Align CAP-03.S06 workflow-profile authority

Status: pending independent packet review and explicit exact-commit human
approval; non-executable.

Proposed authority: `W1.A06`, ordered after adopted `W1.A01`–`W1.A03`, the
terminal `W1.A04` reservation superseded by `GOV-MIG-0001`, and adopted
`W1.A05`.

Classification: the conservative v4
`product-scope-security-experience` envelope. This packet changes product-scope
planning authority only. It does not change security behavior or the governed
experience; it binds the already approved `RO-UI-ACADEMIC-MINIMAL-1.5`
workflow catalog.

## 1. Decision requested

Approve one append-only W1 amendment with one CAP-03 contribution and one
small task:

- `W1.A06.S01 / W1.A06.T01` replaces the isolated
  `CAP-03.S06.T01` acceptance criterion that says “exactly eight built-in
  profiles” with the already approved fourteen-workflow contract, removes the
  unsupported built-in/extension-pack split, and regenerates derived planning
  views.

The exact replacement is:

> All fourteen workflow profiles in the approved workflow catalog are
> represented at its governed version; additions or changes require a
> versioned, reviewed workflow catalog and governed reference update.

No production code, runtime behavior, schema, migration, interface, or visual
design changes in this amendment. After the amendment is independently
completed and adopted, ordinary W1 may resume and claim `CAP-03.S06.T01` under
the corrected authority.

## 2. Evidence for the conflict

The currently approved planning sources disagree:

- the `CAP-03.S06` slice scope and T01 objective require the fourteen approved
  use cases;
- T05 requires deterministic end-to-end coverage across all fourteen;
- the human-approved `RO-UI-ACADEMIC-MINIMAL-1.5` approval makes fourteen
  workflow profiles normative, and its governed `WORKFLOW_CATALOG.json`
  contains fourteen profiles without a built-in/extension distinction; but
- the first T01 acceptance criterion in the canonical backlog and slice plan
  alone says exactly eight built-in profiles and introduces a versioned profile
  pack that no higher-authority source defines.

The “eight” criterion cannot be implemented together with the objective, T05,
and governed experience without inventing an unapproved tier. Current product
code has not implemented `CAP-03.S06.T01`, so the correction is made before a
task claim and does not rewrite completed behavior.

## 3. Selected resolution

The selected resolution follows product vision and the approved experience:

1. Treat all fourteen governed catalog entries as the W1 workflow-profile
   contract.
2. Retain versioned, reviewed evolution, but bind it to updates of the workflow
   catalog and governed reference rather than inventing a separate extension
   pack.
3. Preserve all other T01 criteria: stage-state semantics and append-only
   profile revision with impact preview.
4. Preserve the complete slice objective, task order, dependencies, estimates,
   implementation boundaries, T02–T05 contracts, W1 exit obligations, and
   approved experience bytes.

This is an authority correction, not refactoring. The refactor allocation is
zero of the immutable 194-point W1 baseline.

## 5. Alternatives

1. **Align T01 to all fourteen approved workflows — selected.** This is the
   smallest coherent resolution and follows both the approved slice outcome and
   governed reference.
2. **Implement only eight workflows.** Rejected because it contradicts the
   slice scope, T01 objective, T05, and approved experience.
3. **Invent six extension profiles.** Rejected because the governed catalog has
   no such classification and the approved plan does not define a profile-pack
   authority or loading boundary.
4. **Reduce the governed catalog to eight.** Rejected because it would be a new
   experience decision, remove approved use cases, and expand the amendment far
   beyond the isolated defect.
5. **Defer CAP-03.S06.** Available but not recommended; it would leave W1
   incomplete even though the conflict is planning-only and safely correctable
   before implementation.
