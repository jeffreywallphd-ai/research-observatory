## 11. Performance and resource budgets
- Benchmark SQLCipher open, representative queries, migration, integrity check, and backup on minimum hardware.
- Avoid repeated KDF work by using random raw database keys wrapped by the profile vault, not a user passphrase for every open.
- Idle lock should not terminate durable jobs whose policy explicitly permits local continuation.

The implementation must record the hardware/OS, fixture version, warm/cold state, repetitions, percentile or distribution used, and a regression threshold. A budget may be refined by benchmark evidence, but relaxation requires review and must not conceal algorithmic or resource regressions.

## 12. Observability and provenance
- Audit secret access by capability/purpose and record lock, unlock, key rotation, rekey, retention, and policy decisions without secret values.
- Expose cryptographic/profile versions and integrity status in diagnostics.

Runtime telemetry and support diagnostics are distinct from durable scholarly provenance. Both use trace/correlation identifiers, but default diagnostics must exclude research content, secrets, raw documents, manuscript text, and sensitive query terms.

## 13. Adjacent-slice handoffs
- CAP-02.S02 opens SQLite only through this protection profile.
- CAP-02.S03 uses the profile vault to wrap object keys.

## 14. Migration and backward compatibility
- Plaintext-to-protected conversion uses verified export into a new encrypted database and requires explicit user approval.
- Cryptographic parameter changes are versioned and supported through rekey/migration, not silent defaults.

Every compatibility-sensitive artifact records its format/schema/protocol/parser/component version. Breaking evolution requires an accepted ADR, tested migration or bridge path, and explicit behavior for older projects/clients.
