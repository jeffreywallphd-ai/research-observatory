# ECR-0011 — approved 1.8 desktop activation

This append-only proposal requests a narrow authority to bind the **already
approved** Academic Minimal 1.8 reference to the desktop verification and
assembly consumers. It is non-executable. The later exact-hash packet needs
independent committed-candidate review and explicit repository-owner approval;
neither this page nor the owner's earlier W2, W2.A01, W2.A02, or 1.8 design
approval grants W2.A03 activation authority. Approval would authorize only the
ordered amendment below, not ordinary task completion, W2 release, or a new
researcher-facing design.

## Decision and why it is needed

**Recommended:** add W2.A03.S01 with two ordered tasks. First, authenticate the
exact 1.8 presentation delta and extend the protected continuation gate for
one future activation segment. Second, rebind the desktop activation,
assembly, and guarded visual baseline to the same approved package. Adopt the
amendment only after independent task, integrated-slice, exit, and
control/security reviews. W2 remains paused until a separate legal resume.

The 1.8 design was explicitly approved and published at
`acdc67b616f5ecdec448f57a7efe46e4f359aa9f` without subsequent
`design/ui-reference/` byte changes. Its current package digest is
`cd8995fdcea2fe44452eaa1fdd258b6f9fab5714cbd443a81a8e5b4251220b94`.
The prepublication proposal digest in its approval record is a different
artifact and must not be used as the active desktop digest. The desktop
extension, baseline, and both assembly scripts still select 1.7. The existing
presentation verifier permits only identity/version and appended-region
deltas, whereas the approved 1.8 catalog also changes exact dates, purposes,
capability/page membership, and inserts four ordered regions. Changing the
protected verification/baseline consumers or gate outside their reviewed
authority would silently cross an approved-design boundary. The current
failed 1.8 capture is an adverse result, not evidence that the existing 1.7
baseline can be relabeled.

Leaving W2 paused is safe but leaves its approved acquisition outcome
incomplete. A 1.9 redesign is appropriate only if subsequent conformance
shows a material experience change; it would require its own design-first
reference decision. Shortening CAP-05.S01.T01's original base, borrowing a
historical contract, hand-editing screenshot hashes, or broadening generic
gate/maintenance allowances cannot qualify this change.
