Academic Minimal Style Guide

Implementation specification for the preferred Research Observatory visual system across light and dark themes.

Page index
Approved experience reference: Academic Minimal 1.3
Crisp white and cool-gray light surfaces, deep navy dark surfaces, restrained royal-blue interaction accents, serif display headings, compact sans-serif workbench text, and minimal decorative effects. Tokens, semantics, page contracts, and required interaction behavior are normative; names, counts, vendors, sample prose, and inactive mock actions are illustrative.

1. Visual principles

The interface should communicate rigor before novelty and depth before decoration.

Evidence before prose

Primary actions expose sources, passages, status, and uncertainty. Generated prose is downstream.

Quiet structure

Use borders, spacing, alignment, and typographic hierarchy before shadows or color.

Blue means interaction

Royal blue identifies selection, active navigation, links, focus, and primary actions—not all data.

State colors have fixed meaning

Semantic and evidence-state colors must not be reassigned by page or chart.

7. Behavior and accessibility

Desktop-first does not mean mouse-only or visually dependent.

Keyboard

Visible focus ring; logical tab order; workspace landmarks; keyboard-accessible graph alternatives; Escape closes transient surfaces.

Motion

120–180 ms transitions. No essential meaning in animation. Respect reduced-motion settings and disable large graph transitions.

Contrast

Target WCAG AA for text and controls. Use color with labels, icons, shapes, patterns, or table columns.

Staleness and controlled recalculation

Dependency changes remain visible and researcher authority remains explicit.
Never overwrite

Explain. Name the material cause, affected object, and safest next action. Deferral preserves the stale label.

Classify. Group preview rows as automatic, review required, blocked, or informational after current rights and egress checks.

Version. Recalculation and restoration create immutable revisions; adjudicated outputs require an exact human review decision before activation.

9. Experience-reference governance

Intentional user-facing changes are designed and approved here before implementation.

Normative

Design tokens, semantic state meanings, page routes, required regions, navigation, interaction and accessibility behavior, and light/dark parity.

Illustrative

Mock names, counts, studies, provider examples, dates, prose, charts, and nonfunctional actions. They do not authorize backend scope.

Design-first change order

Update the style guide and affected HTML page contracts, regenerate and validate the reference, obtain human approval, then claim the implementation task and attach conformance evidence.

Reference viewport and responsive obligation
Baseline visual captures use 1440 × 900 in light and dark themes. The product must remain usable at 1280 × 720 and at supported desktop scaling from 100% through 200% on Windows x64, macOS Apple Silicon, Linux x64, and Linux ARM64; responsive collapse must preserve all functions and keyboard access.

10. Guided workflow and adaptive navigation

The interface is organized around scholarly objectives rather than presenting every workspace as an equal disconnected tool.

Primary use case

Selected during project creation and governed by the Research Intent Contract. It controls ordered steps, defaults, checkpoints, recommended outputs, and next-step rationale.

Guided workflow

Numbered steps use 28 px markers, 40 px minimum rows, brand blue for current, success green for complete, neutral slate for upcoming, violet outline for optional, and warning amber only for attention.

All tools remain available

A secondary “All tools” disclosure preserves expert access. When a user opens a supporting tool, the context bar explains that it is outside the primary sequence and offers a return to the current step.
