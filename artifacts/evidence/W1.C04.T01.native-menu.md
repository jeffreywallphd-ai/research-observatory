## Prospective fixture-only C experiment

Defer only space-triggered `SC_KEYMENU` received in an unreplied synchronous
send. Retain its exact arguments in one fixture-owned pending slot and post a
scalar replay token to the same window. Checked non-reused tokens, consume before
forward, and teardown invalidation prevent stale, unsolicited or nested replay
from opening another menu or replacing a newer pending action. No state borrow
may span default window processing. A failed post forwards the original only
while its own live reservation remains; no IPC or policy authority changes.

If another request arrives while that slot is occupied, preserve baseline
forwarding rather than drop, overwrite or silently coalesce it. This overlap can
still exhibit the known stall and is explicitly unqualified, not a production
fix. Independent design preflight supports this bounded causal experiment only.
Native C must demonstrate continuing status delivery while the menu is open,
Escape dismissal and live follow-on UI, retaining the unchanged timeout and
failure latch. Production activation requires evidence and separate review.
