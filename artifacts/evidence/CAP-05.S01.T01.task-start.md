## Precommit audit: unresolved command after restart (2026-10-03)

Source review identified a recovery gap before the first picker/commit run. Core correctly reports an unresolved old-session command as `stale-session` with a null command ID, but the native status decoder treats that null as a mismatched command and returns no result. The pane can then retain an `unconfirmed` saved decision with `retryHeld`, disabling both retry and return. The approved boundary requires old random sessions never to replay and an unresolved attempt after restart to require a fresh stage; a user must not be trapped on that stale decision.
