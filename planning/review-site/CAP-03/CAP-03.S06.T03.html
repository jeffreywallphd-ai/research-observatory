## Authority-bearing navigation fields

- Project: project ID, canonical root, compatibility/access state, open state.

## R01 adverse-review learning

- `CAP-03.S06.T03-R01-F01`: the persisted-Intent callback carried no invocation-time project/generation witness. A delayed project-A save or acceptance could therefore call its retained callback after unmount, invalidate project B's active loader, and install A's projection beneath B's shell. Add a project-bound callback envelope and deny it unless project ID/root still match the current shell; cancel all workspace-owned asynchronous mutations on unmount. First regression: delay save and acceptance independently, replace A with B, release A last, and prove B remains/loadable as the sole authority.
- `CAP-03.S06.T03-R01-F02`: the supporting return copied only the portable profile catalog identity and omitted the separately exposed governed-reference and intent-guidance identities. Carry reference ID/version and intent guidance version/hash through `WorkflowAuthoritySnapshot` and `SupportingReturnContext`, compare each field, and add one-field substitution tests.
- Incremental review boundary: replay both findings, the existing complete-projection authentication tests, persisted-versus-unsaved selection behavior, application lock clearing, supporting-return success/expiry, exact UI lineage, and the focused assembled-browser product check.
