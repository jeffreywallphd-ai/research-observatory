## Separate reproduced packaged-resource validation defect

The successful live process started Core from the repository's debug fallback
package, not its colocated `runtime/core-sidecar`. The actual Core executable hash
matches the frozen study build (`0ebd3bc60277e5d23fd7be54007ac64d029131ff1f0e32df457d78b6f9c5af9a`).
All 710 files, individual sizes/hashes and total file count match the existing
study Core inventory (zero mismatches). No mocked transport or substitute Core
was used. This nevertheless does not qualify a standalone/release copy.

A [read-only probe](W1.usability-blind-01.resource-probe.rs) calls the actual
compiled `SupervisorConfig::from_resource_root`, never starting Core or opening a
window. It reproduced:

```text
supplied_root=C:\workspace\research-observatory\artifacts\tmp\ux-blind-20260905a\runtime
std_canonical_root=\\?\C:\workspace\research-observatory\artifacts\tmp\ux-blind-20260905a\runtime
supplied_result=Ok("accepted")
std_canonical_result=Err("RO-CORE-INTEGRITY-FAILED")
```

Both inputs refer to the same existing test package. The pinned Tauri
`tauri-utils-2.9.3/src/platform/starting_binary.rs` caches the standard-canonical
executable path; `platform.rs::resource_dir_from` returns its parent on Windows.
The current supervisor instead compares its input byte/path representation to
`dunce::canonicalize`, which removes the ordinary verbatim prefix. Consequently
the standard-canonical resource representation is rejected. `lib.rs::runtime_config`
then uses the debug-only fallback. This code-path explanation is supported by the
real compiled probe and the actual fallback child path; it is **not** an explanation
for the earlier UI hang. Release behavior without fallback remains to be
qualified by an actual release build.

Candidate closure, through the applicable approved work/review lane: normalize
equivalent legitimate Windows path representations consistently before identity
comparison, retaining exact executable allowlisting and rejection of redirected,
substituted and non-file targets; add a real Tauri-resource-root packaged startup
test with no repository fallback. Do not simply drop the integrity check, add an
environment override, or bypass Core security. This report records a finding,
not authority to broaden an approved task's scope.
