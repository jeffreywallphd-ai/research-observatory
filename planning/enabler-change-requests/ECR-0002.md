## 4. Selected design

### 4.1 W1.A03.B00 — cumulative UI-gate correction

The bootstrap may change only:

- `tools/ui_change_gate.py`; and
- `tests/foundation/test_ui_change_gate.py`.

The correction removes the unconditional demand for a post-implementation protected hardening commit when all protected changes are strictly before the first UI implementation commit and each such change passes the existing additive pre-implementation quality-inventory validator. It does not weaken any other condition.

Required behavior:

1. The exact cumulative range `bfb8797…59079ef` passes with the unchanged approved reference and UI evidence contract.
2. A malformed additive inventory remains denied.
3. Any protected control and UI implementation in the same commit remains denied.
4. A protected change after UI implementation still requires the existing exact independent-review hardening envelope and historical attestation.
5. Multiple protected commits must all be classified exactly; mixed, omitted, reordered, or unrecognized control changes fail closed.
6. Non-application UI paths, intentional design changes, reference approval, self-approval, Git-object safety, and canonical policy checks remain unchanged.

The bootstrap is independently reviewed before task materialization. It may not change product code, the UI reference, `ui-change-policy.json`, `architecture-protected-paths.json`, T03 state/evidence, or ordinary W1 state.

### 4.2 W1.A03.T01 — exact historical candidate recovery control

T03 cannot truthfully use the current governance HEAD as its product implementation commit: the actual product candidate is `59079ef…`, while all later commits are review, amendment, and recovery control history. T01 therefore adds a narrow exact-candidate recovery transition rather than laundering the later history into T03 evidence.

The transition must:

1. target only `CAP-02.S04.T03` under `HOLD-W1-GRR-0001` and this exact approved W1.A03 packet;
2. remain denied until W1.A03 is `ADOPTED`, its control/security checkpoint is present, GRR-0001 is `RELEASED`, W1 is explicitly resumed with scope `wave`, and T03 remains `BLOCKED` at the recorded reason/boundary;
3. require a canonical repository-local recovery manifest that binds the exact base, foundation, candidate, UI evidence contract, block record, pause record, branch, task, reference identity/package/approval, changed paths, selected checks, and zero unverified items;
4. independently recompute Git existence, ancestry, exact base-to-candidate paths, immutable contract bytes, the repaired cumulative UI gate, and risk-selected product/privacy checks against the historical candidate;
